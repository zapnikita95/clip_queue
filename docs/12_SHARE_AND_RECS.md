# Share → auto-categorize → push (product north star)

## Как пользователь кладёт видео

1. В YouTube находит ролик → **Поделиться → Clip Queue** (PWA / будущее нативное приложение).
2. Клиент дергает `POST /api/videos/save` с URL (уже есть).
3. Бэкенд:
   - резолвит метаданные;
   - **не** кладёт музыку/≤6мин в план (archive);
   - применяет **сохранённые classify_rules** пользователя (`organize.apply_rules_to_video`);
   - опционально лёгкий LLM-тег, если нет матча по правилам;
   - (фаза 2) пуш: «Сохранили в „История“ — посмотрим?»
4. Пользователь открывает приложение позже → очередь по темам → тап → YouTube.

## Почему не весь «Смотреть позже»

YouTube Data API **не отдаёт** системный плейлист `WL` (часто `totalResults: 0` даже при 800+ в UI).  
Синк = лайки + обычные плейлисты. Обход: пользовательский плейлист-копия или share по одному.

## Рекомендации «лучше чем YouTube»

Близость без тяжёлого ML:

- тот же `theme` rule / канал / пересечение тегов;
- rail `continue_vibe` уже ранжирует по каналу/тегам/длине;
- не предлагать music/shortform/unavailable;
- «похожие с других каналов про историю» = theme match + diversify channel.

Ресурсы: heuristic + дешёвый LLM только на share без матча.
